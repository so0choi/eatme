# Eat me 모바일 v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 공유 도메인 패키지·모바일 대응 인증/푸시 백엔드·웹 보강·Expo 앱을 만들어 스토어 출시 가능한 v1 코드베이스를 갖춘다.

**Architecture:** `packages/core`(순수 TS 도메인 로직)를 web/mobile이 공유. NestJS GraphQL API에 refresh rotation·기기 세션·Apple 로그인·계정 삭제·약관·푸시를 추가하고 in-memory Prisma e2e로 검증. `apps/mobile`은 Expo Router + Apollo + NativeWind.

**Tech Stack:** pnpm workspace, NestJS 11 + Fastify + Prisma 7, Next.js 16, Expo SDK(최신 안정) + Expo Router, Apollo Client 4, NativeWind, vitest, jest(ts-jest / jest-expo), jose.

**Spec:** `docs/superpowers/specs/2026-11-03-mobile-v1-design.md` — 모든 태스크는 스펙과 함께 읽는다.

## Global Constraints

- 모든 태스크 종료 시 루트 `pnpm verify` 통과. 실패 상태로 커밋 금지.
- API 컨벤션은 `apps/api/CLAUDE.md` 준수: env는 `ConfigService`, 리다이렉트는 `@Redirect()`, 검증은 zod DTO(`static isZodDto = true; static schema = …`), 예외는 `HttpException` 계열.
- 웹 UI는 `apps/web/AGENTS.md` 디자인 토큰 규칙 준수. 모바일 NativeWind 토큰도 같은 이름(`primary`, `surface-container-low` 등)과 값을 사용.
- 새 Prisma 메서드를 서비스에서 쓰면 `apps/api/test/support/in-memory-prisma.ts`에도 구현.
- 스키마 변경 후 `pnpm --filter eatme-back prisma:generate`. DB 연결 명령(`migrate dev`, `db push`) 실행 금지.
- 비밀값·키는 코드에 하드코딩 금지. 미설정이어도 앱/서버가 부팅되고 해당 기능만 비활성(경고 로그).
- 상수: `TERMS_VERSION = '2026-11'`, 기본 `pushHour = 9`(KST), access 15분, scheme `eatme`, 기본 번들 ID `com.eatme.app`.
- 커밋 메시지는 한국어 conventional commit, 끝에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- 브랜치: Phase마다 하나(`feat/mobile-core` → `feat/mobile-api-auth` → `feat/mobile-api-push` → `feat/mobile-web` → `feat/mobile-app`), 각 브랜치는 직전 Phase 브랜치에서 생성. main 직접 커밋·push·병합 금지.

## Review Focus

1. 회전된(이미 사용한) refresh token을 다시 쓰는 경우(앱 재개 + 다른 탭 동시 갱신) → 서버는 `UNAUTHENTICATED`, 크래시·세션 중복 없음. → Task 4 테스트.
2. refresh까지 만료된 상태로 앱을 연 경우 → 갱신 1회 실패 후 로그인 화면, 무한 재시도 없음. → Task 15 테스트.
3. KST 날짜 경계: `expireAt`이 UTC 기준 전날 15:00~23:59(=KST 당일)인 재료도 "오늘/내일" 판정에 포함. → Task 12 테스트.
4. Apple 재로그인 시 `name` 미전달 → 기존 유저면 이름 유지, 신규면 email을 이름으로. → Task 7 테스트.
5. Apple 키 미설정 상태에서 Apple 계정 삭제 → revoke는 건너뛰고 삭제는 완료. → Task 8 테스트.
